# Lineage of snapshot #102 — pancreatic adenocarcinoma, v8

**This record was reconstructed on 12 Sep 2026, seven weeks after the harvest.** It was not
written by the harvest. Every entry above says how confident the reconstruction is; treat
`confidence: low` and `medium` entries as best-effort, not as the run's own testimony. When
this snapshot's `provenance.runs` is later written into Oracle, that record supersedes this file.

## How it was reconstructed

1. **When each axis ran** comes from `EVIDENCE.retrieved_at`, which `saveAxisEvidence` stamps at
   write time. Every row of an axis shares one save, so one gene's timestamps (KRAS was used)
   give the whole timeline: ten axes on 24 Jul between 11:42 and 15:00, proteomics on 4 Aug,
   network on 5 Aug.
2. **Which code ran** is the last commit touching `scripts/d2t.ts` before each timestamp
   (`git log --until`). For the 24 Jul runs that is `17c5e0e`, committed at 11:58 — twenty
   minutes *after* the harvest started at 11:38. So those runs executed on the working tree
   that became `17c5e0e`. The formulas quoted above were checked against
   `git show 17c5e0e:scripts/d2t.ts`, not against today's file.
3. **Which reference data** comes from the `meta.built` field inside each `data/*.json` and
   the commit that last changed the file.
4. **What the harvest itself recorded** is exactly `{ "source": "Open Targets associatedTargets",
   "via": "scripts/d2t.ts" }`. The candidate cutoff and Open Targets release were not written
   down; they are inferred from the gene count (6,189) and the date. Snapshots #103 and #123,
   harvested after `candidateProvenance()` was added, record both.

## What is uncertain, plainly

- **Open Targets release** for the harvest, annotation, druggability and clinical runs:
  inferred 26.06 from the date. Not recorded.
- **Candidate cutoff**: inferred "top 6,000". The stored count is 6,189, which is the same
  over-shoot the later snapshots show when ties at the cut are kept.
- **Network node-set size**: the code default is 800, the store has 1,659 network rows, so the
  environment override `WINNER_NETWORK_N` was set to something larger and its value is lost.
- **Druggability label→score map**: read from today's `evidenceProviders.ts`; that file was
  last changed in `17c5e0e` on the same day, so the map is almost certainly the one that ran.

## Why `annotation`, `literature` and `patents` have `axis: null`

They are stored as evidence rows for the dossier and the co-pilot but carry `role: annotation`
and are never ranked on. The board's Expression, Dependency, Safety, Tissue, Mutation,
Druggability, Clinical, Literature (Europe PMC), Proteomics and Network criteria are the
scored ones.
