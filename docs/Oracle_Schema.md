# Oracle Schema — Disease2Target content store

Plain-English reference for the Oracle database. The runnable DDL lives in
[`sql/`](sql/) (`oracle_target_ranking_snapshots.sql`, `oracle_content_tables.sql`).

---

## Big picture

Oracle is the **content store of record** — every ranking, score, evidence item, and event lives
here, traceable. (Supabase is auth-only.) The browser never touches Oracle:

```
Browser (React) → server.ts endpoints → oracleService.ts (node-oracledb) → Oracle (4 tables)
```

There are **4 tables**, in a snapshot-centric shape:

```
TARGET_RANKING_SNAPSHOTS   (parent — one row per harvest/ranking run)
        │ id
        ├──< RANKING_SCORES   (child — one row per gene per snapshot: the scores)
        └──< EVIDENCE         (child — one row per gene per source: the evidence + provenance)

AUDIT_LOG                  (independent, append-only event trail)
```

---

## 1. `TARGET_RANKING_SNAPSHOTS` — the parent

One row per **harvest / ranking run** (a "snapshot"). Think of it as "the pancreatic study, Tier 2."

| Column | Meaning |
|---|---|
| `id` | auto identity PK — children link to this |
| `disease_id` | EFO/MONDO id (e.g. `MONDO_0006047`) |
| `disease_name` | human name |
| `version` | the run number for this disease — **shown in the UI as "Tier N"** |
| `created_at` | `SYSTIMESTAMP` |
| `created_by` | user/agent |
| `label` | note (e.g. "Harvest", "Job harvest") |
| `gene_count` | number of genes in the run |
| `weights` | JSON — GET weights used |
| `provenance` | JSON — sources, app version, retrieved date |
| `targets` | JSON (CLOB) — the full ranked gene blob |

**Note:** `version` is the field the app now labels **"Tier"** in the UI (Funnel/Rankings pickers).

---

## 2. `RANKING_SCORES` — per-gene scores (child)

**One row per gene per snapshot.** The queryable, flattened scores (good for SQL/benchmarking).

Key columns: `snapshot_id` (FK → snapshots, **ON DELETE CASCADE**), `disease_id`, `gene_symbol`,
`gene_name`, `rank_position`, `overall_score` (OT association), `get_score`, `genetic_score`,
`expression_score`, `target_score`, `literature_score`, `tau_tissue`, `tau_single_cell`,
`bimodality_max`, `pubtator_score`, `created_at`.

The funnel reads `genetic_score`, `target_score` (druggability), `tau_tissue` etc. from here; the
3 new axes (safety/dysregulation/dependency) come from EVIDENCE, not here.

---

## 3. `EVIDENCE` — per-gene evidence with provenance (child) ⭐

**The extensible heart of the system. One row per `(gene, evidence_type, source)`.**
Adding a new evidence source = **new rows, no schema change.**

| Column | Meaning |
|---|---|
| `id` | auto identity PK |
| `snapshot_id` | FK → snapshots (**ON DELETE SET NULL** — evidence may be snapshot-less, e.g. paper evidence) |
| `disease_id`, `gene_symbol` | what it's about |
| `evidence_type` | the kind — see list below |
| `source` | named source (gnomAD, DepMap, ChEMBL, cBioPortal, ClinicalTrials.gov, …) |
| `source_url` | link to the source record |
| `value_text` | short human-readable string (VARCHAR2 — keep **ASCII/Latin-1**, see gotcha) |
| `value_json` | structured payload, CLOB with **`IS JSON`** check — the **contract** (below) |
| `retrieved_at`, `generated_by`, `audit_status` | provenance (`not_audited` / `ai_verified` / `human_verified`) |

### `evidence_type` values
- Original: `clinical`, `literature`, `druggability`, `mutation`, `paper`, `genetic`, `expression`, `tissue`
- **Added this cycle:** `safety` (gnomAD), `expression_tvn` (tumor-vs-normal dysregulation), `dependency` (DepMap)

### The `value_json` contract (every new row carries this)
```json
{ "axis": 0.0-1.0, "direction": "pro|con", "display": "human text", "...raw fields": "log2fc / loeuf / mean / ..." }
```
- `axis` — normalized 0–1, what the funnel **ranks** on.
- `direction` — `pro` (high is good) or `con` (high is a concern, e.g. safety).
- `display` — short text for the matrix/card.
- raw fields — the real numbers, kept so **filters** work in real units (log2FC, LOEUF…).

---

## 4. `AUDIT_LOG` — append-only trail (independent)

Immutable event log: `event_time`, `actor`, `action` (`snapshot_saved` / `harvest_saved` /
`evidence_saved` / `genes_added` / …), `entity`, `entity_id`, `disease_id`, `details` (JSON).
The runtime role has **SELECT + INSERT only** (no UPDATE/DELETE) so history can't be rewritten.

---

## Conventions & gotchas (important)

- **Identity PKs** (`NUMBER GENERATED BY DEFAULT AS IDENTITY`). Inserts use `RETURNING id INTO`.
- **JSON columns have an `IS JSON` check** → never insert a bare scalar/`null`. Use `{}` / `[]`.
  The `clob()` helper in `oracleService.ts` enforces this (`JSON.stringify(obj ?? {})`).
- **Timestamps**: `DEFAULT SYSTIMESTAMP` (don't pass JS dates as strings for created_at/event_time).
- **DB charset is NOT full UTF-8** → keep `value_text`/`value_json` strings **ASCII/Latin-1** safe
  (▲▼→ get mangled to `¿`; `·` is fine). Use `up`/`down` instead of arrows.
- **Owner vs app role**: tables are owned by `DISEASE2TARGET_OWNER`; the app connects as
  `DISEASE2TARGET_APP` (RW role `DISEASE2TARGET_RW`) via public synonyms. `oracleService.ts`
  prefixes table names with `ORACLE_SCHEMA` via the `T()` helper.
- **Gated by `USE_ORACLE_STORE=1`** and the Oracle env vars (`.env`, UTF-8 **without BOM**).
- **VPN required** — the Oracle host is UAB-internal.

## How the app maps to the tables (`oracleService.ts`)

| Table | Writes | Reads |
|---|---|---|
| snapshots | `saveSnapshot`, `saveHarvest`, `addGenesToSnapshot` | `listSnapshots`, `getSnapshot`, `deleteSnapshot` |
| ranking_scores | written inside the above | `listRankingScores` |
| evidence | `insertEvidence`, `saveEvidenceCards`, **`saveAxisEvidence`** (idempotent; gene-scoped option) | `snapshotEvidence`, `evidenceForGene`, `evidenceGeneSymbols` |
| audit_log | `logAudit` (inside transactions) | — |

Server endpoints that surface these: `/api/snapshots*`, `/api/harvest`, `/api/evidence*`,
`/api/jobs*`, `/api/oracle/health`. The Funnel/Rankings/Jobs views read snapshots+scores+evidence
through `supabase.ts` client helpers (`fetchSnapshots`, `fetchSnapshotScores`, `fetchSnapshotEvidence`).

---

## Quick mental model
- **A snapshot** = one harvest run for a disease (= a "Tier" in the UI).
- **ranking_scores** = the genes + their scores in that run.
- **evidence** = the per-gene, per-source facts behind those genes (this is where new axes plug in — one `evidence_type` + the `value_json` contract).
- **audit_log** = who did what, when (tamper-proof).
