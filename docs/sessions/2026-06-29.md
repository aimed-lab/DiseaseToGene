## 0. 30-second orientation

**Disease2Target** = an AI-assisted **drug-target discovery & evidence-ranking** web app.
Enter a disease → pull genes from Open Targets → score & enrich with multi-source evidence →
narrow to a justified shortlist through a **multi-tier funnel** → nominate targets.

- **Stack:** React 19 + TS + Vite + Tailwind (UI mostly in `index.tsx`). Express backend `server.ts`.
- **Content store of record:** **Oracle** (4 tables). Supabase = auth only.
- **Dev:** `npm run dev` (= `tsx --env-file=.env server.ts`, port 3000). **`tsx` does NOT auto-reload — restart after any `server.ts`/`oracleService.ts` change.**
- **Verify:** `npx tsc --noEmit` and `npm run build` (both must pass; they do).
- **Oracle is UAB-internal → needs VPN.** This agent environment **cannot** reach Oracle; it CAN reach public APIs (Open Targets, gnomAD, etc.).
- **Repo:** GitHub `aimed-lab/DiseaseToGene` (origin). Pushed up to commit `b87c202`+ (see git log).

**Design doc (the professor's gate):** `docs/Disease2Target_Funnel_Design.md` — the cost-ordered tier funnel.

### Registry + value_json contract (the extensibility foundation)
- `evidenceRegistry.ts` — **single source of truth** for the funnel tiers. Each axis declared once:
  `tier, label, source, type (hard/soft), direction (pro/con), weight`, and a **filter** definition.
- **`value_json` contract** every EVIDENCE row carries: `{ axis (0–1, for ranking), direction, display, ...raw fields }`.
  Adding a new evidence source = **one registry line + write the row** (no schema change, no funnel rewrite).
- **Filters use each axis's RAW value in real units** (log2FC, LOEUF, Chronos, trials…), NOT the normalized axis. `axis` is only for ranking/composite.

### Funnel redesign (`FunnelView.tsx`)
- Vertical **tier pipeline**, T0 at top → narrows downward (cards shrink with their count).
- **Tier names on the left, counts on the right.**
- Removed the always-on shortlist; **gene list is on demand** ("View genes" button / composite tier).
- Each tier expands to its **own raw-value filter** (range slider / category checkboxes).
- **Direction-aware composite** (safety is `con` → high constraint lowers rank).
- Pending axes shown greyed.

### Background Jobs feature (`JobsView.tsx` + job engine in `server.ts`)
- In-process **background job queue** (one at a time), persisted to `data/jobs.json`. Endpoints: `POST/GET/DELETE /api/jobs`.
- **Harvest job** (`type: harvest_ot`): disease + gene count → pulls Open Targets universe → snapshot in Oracle, then **enriches** each gene with safety/dysregulation/dependency evidence (the 3 axes).
- **Add-genes job** (`type: add_genes`) — NEW: paste gene symbols (e.g. `SRC`) + pick a snapshot → looks up each gene's real OT association, **appends it to that snapshot's universe**, and enriches it. Lets a researcher inject genes that join the same funnel. (This is the professor's "Tier-1 open ingestion".)
- **Oracle data browser** (right pane of Jobs tab): inspect any snapshot's scores + evidence tally.

### On-demand gene drawer (`GeneDetailDrawer.tsx`)
- Slide-over that opens for **any** gene symbol (incl. the 7k snapshot genes never search-loaded). Reuses the existing panels (they fetch by symbol). Wired into Funnel (gene list) and Rankings (click gene name).

### Other
- Renamed snapshot **"version" → "Tier"** across Funnel/Rankings/toasts.
- Fixed: Funnel/Rankings/Jobs tabs now open **without** a disease search (they're DB-backed).
- Fixed: **encoding** — replaced ▲/▼ in stored `value_text` with ASCII (`up`/`down`); the Oracle DB charset isn't full UTF-8 (it mangled ▲ → `¿`). **Keep stored strings ASCII/Latin-1 safe.**

## 3. Key design decisions (agreed this session)

1. **Tiers ordered by COMPUTE COST** (professor's feedback): cheap API/search first → differential expression / network mid → foundation-model / molecular-dynamics last. (Registry not yet re-numbered to this — pending.)
2. **Tiers are silos that ACCUMULATE from many sources; the transition is a SIFT** (explicit criterion). Funnel is iterative over rounds; candidates carry lineage.
3. **Evidence must come from the REAL sources, not Open Targets alone.** OT = universe assembly; evidence = ClinicalTrials, cBioPortal, ChEMBL, Europe PMC/PubTator, gnomAD, DepMap, TCGA/GTEx.
4. **Bulk over per-gene.** Most real sources have a **disease/cohort-level bulk pull** (cBioPortal one cohort call; ClinicalTrials one disease query) or a **one-time global download → reference table** (gnomAD constraint TSV, ChEMBL dump, PubTator co-mention files — like DepMap/expression). gnomAD/ChEMBL/PubTator = one-time global; cBioPortal/ClinicalTrials = per-disease.
5. **Cost-tier the harvest:** cheap evidence for the FULL universe; expensive per-gene detail only for SURVIVORS (and for the target card).
6. **Filters on raw values; `axis` only for ranking.**
7. **Tier-1 ingestion is open** (OT now; paper-upload / manual / CSV later). Manual genes JOIN the existing snapshot (not a separate list).

## 4. The SRC case study (the headline)

SRC has a **low Open Targets score** (~0.11–0.39 depending on the pancreatic EFO; ~rank 7,000/20,000) — single-modality buries it. But it's **drowning in real evidence**: 1,339 papers, Clinically Validated (IC50 1.3 nM, 6,507 compounds), over-expressed (log2FC +1.46), a dependency, 12 trials Phase 2. Story: *multi-axis, objective system recovers SRC where single-modality can't.* The add-genes feature lets you inject SRC into a pancreatic snapshot live and watch it surface.

## 7. Gotchas (don't relearn these)

- **VPN required** for Oracle; this agent env can't reach it — build + `tsc`/`build`-verify here, run/test on VPN.
- **Restart `npm run dev`** after server-side edits (`tsx` no reload).
- **Oracle charset isn't full UTF-8** → keep stored `value_text`/`value_json` strings ASCII/Latin-1 (no ▲▼→ etc.). `·` is fine.
- **`data/*.json` reference tables are committed; raw downloads (`xena_raw/`, `depmap_raw/`) and `data/jobs.json` are gitignored.** Regenerate tables via the `scripts/build_*.mjs`.
- Enrichment is **idempotent** (`saveAxisEvidence`): re-running replaces, never duplicates. Add-genes uses the gene-scoped variant so it doesn't wipe other genes.
- gnomAD per-gene is the only slow harvest step today (~mins for hundreds); making it a table removes that.
