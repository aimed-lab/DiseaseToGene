## 0. The goal this session served
Two strict requirements from the user:
1. **Job feature = raw-evidence loader.** Running a harvest for a disease must pull the
   full Open Targets universe and write **every evidence axis we have** as **raw rows**
   into Oracle (snapshots → ranking_scores → evidence), reusable for any case study.
2. **Funnel = consumer.** Reads that stored data as a true top-to-bottom step funnel,
   filters on **raw values only**, and shows the **same numbers the gene drawer shows**.

## 1. What changed

### All 8 axes now write evidence in a harvest (was 4)
`enrichAxes` in `server.ts` previously wrote only `expression_tvn`, `dependency`, `safety`.
It now also writes **`mutation`**, **`druggability`**, **`clinical`**, **`literature`** — so a
single job stores the full axis set as raw `value_json` rows.

| Axis | Source | How it's pulled | Cost |
|---|---|---|---|
| genetic | Open Targets | comes with the snapshot (ranking_scores) | free |
| mutation | cBioPortal | **ONE bulk cohort pull** (`mutations/fetch`) → aggregated per gene | 1 call/job |
| dysregulation | TCGA/GTEx | reference table `data/expression_paad.json` | table |
| dependency | DepMap | reference table `data/depmap_pancreatic.json` | table |
| safety | gnomAD | **NEW reference table** `data/gnomad_constraint.json` (was live per-gene) | table |
| druggability | ChEMBL | per gene (no bulk endpoint), conc=5 | ~4 calls/gene |
| clinical | ClinicalTrials.gov v2 | per gene, disease-scoped, conc=5 | 1 call/gene |
| literature | Europe PMC | per gene, disease-scoped, conc=5 | 2 calls/gene |

### New: server-side evidence providers — `evidenceProviders.ts`
Mirrors the browser drill-down services so **stored evidence == live drawer data**:
`fetchCohortMutations` (bulk), `fetchDruggability`, `fetchClinical`, `fetchLiterature`,
`resolveCbioStudy`. The browser services route through `/api/proxy`; the server calls
upstream directly. All return **raw numbers in real units** (frequency, IC50 nM, trials, velocity).

### New: gnomAD constraint reference table
`scripts/build_gnomad_constraint.mjs` → downloads gnomAD v4.0 constraint metrics (~86 MB,
into gitignored `gnomad_raw/`) → flattens the **MANE Select** transcript per gene →
`data/gnomad_constraint.json` (**17,953 genes**, pLI/LOEUF/oe_lof/lof_z/mis_z). Served at
`/api/gnomad`. The job's `gnomadConstraint()` now reads the table first, live GraphQL only
as fallback — **removes the only slow per-gene step that the safety axis used to be.**
Verified vs gnomAD: KRAS LOEUF 0.264, SRC 0.384, BRCA1 pLI≈0. ✓

### Gene cap raised → full universe
Harvest cap `5000 → 25000`; JobsView adds a **"Full universe (all genes)"** option. The OT
loop stops when associated targets run out, so pancreatic settles at ~7.3k.

### Funnel: raw filters + parity (`FunnelView.tsx`)
- Fixed evidence extraction to read the **actual stored `value_json` keys** (`mut.frequency`,
  `lit.velocity`) — it was reading non-existent keys (`mutationFrequency`, `signal_velocity`).
- Druggability ranking now uses the **stored ChEMBL score**, not the OT `target_score`.
- **Every headline tier now cascades** (T1→T8) when its gate is enabled — not just the hard
  axes. Soft tiers default to pass-through thresholds, so enabling is safe.
- Each tier's filter is the **raw field in real units** (genetic OT score, frequency, log2FC,
  Chronos, ChEMBL category, LOEUF, trial_count, velocity) — matching the drawer numbers.

### Drawer: all 8 axes (`GeneDetailDrawer.tsx`)
Added **`ClinicalPanel.tsx`** + **`LiteraturePanel.tsx`** (fetch `/api/clinical`, `/api/literature`
— the same providers the harvest uses, cached server-side). The drill-down now shows the
full 8-axis set, each matching its funnel tier.

## 3. Gotchas / notes for next session
- **Full-universe jobs are slow.** mutation/safety/expression/dependency are cheap (table or
  1 bulk call), but druggability+clinical+literature are **per-gene** (~7 upstream calls/gene).
  For ~7k genes that's a long background job. Validate with 250–500 genes first, then run full
  universe (e.g. overnight). The job is idempotent so a re-run replaces, never duplicates.
- The job's per-gene providers call upstream **without** the server `/api/*` cache (the drawer
  endpoints DO cache). A future optimization: route job calls through the cache too.
- **Literature counts are Europe PMC free-text** (`"SYMBOL" AND "disease"`) — noisier than
  PubTator gene annotation (SRC shows ~13k not the PubTator ~1.3k). Velocity (the funnel field)
  is the robust ratio. Swap to PubTator co-mention later if you want cleaner absolute counts.
- Keep stored `value_text`/`value_json` strings **ASCII/Latin-1** (DB charset). New providers
  use `·` (ok) and plain words only.
- `gnomad_raw/` is gitignored; regenerate the table with `node scripts/build_gnomad_constraint.mjs`.
